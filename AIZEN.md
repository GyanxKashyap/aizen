# Aizen — Complete Model Card & Build Reference

**Aizen** is a 40-million-parameter decoder-only Transformer, trained entirely
from scratch on a MacBook Air. Current release **v6** (`aizen_phase8.pt`).

No `transformers`. No `tiktoken`. No pretrained weights. The architecture, the
byte-pair tokenizer, the training loops, the benchmark and the interface were
all written for this project and are all in this repository.

This document records **everything** that went into the model — every data
source and its licence, every token count, every hyperparameter — so it can
serve as a complete reference for building your own.

| | |
|---|---|
| Release | **v6**, `aizen_phase8.pt` |
| Parameters | **40,188,928** (40.19M) |
| Layers / dim / heads | 12 / 512 / 8 |
| Context | 512 tokens |
| Vocabulary | 4,096 (from-scratch BPE) |
| Benchmark | **60.75%** on 400 frozen questions (baseline 17.0%) |
| Hardware | one MacBook Air, Apple silicon, PyTorch MPS |
| Predecessor | v0, `aizen.pt` — 14.3M, character-level (Appendix A) |
| Sibling | Aizen Storyteller, `aizen_phase8_pretrained.pt` — the same weights before fine-tuning |

## 1. Data — every source used

Aizen's training data comes from **three** places. Two are public datasets; one
is generated by scripts in this repository. Nothing was scraped, and no
pretrained weights were used at any point.

### 1.1 TinyStories — the pretraining corpus

| | |
|---|---|
| Source | `roneneldan/TinyStories` (Hugging Face) |
| Paper | Eldan & Li, *TinyStories: How Small Can Language Models Be and Still Speak Coherent English?* (2023) — https://arxiv.org/abs/2305.07759 |
| Licence | listed on Hugging Face as CDLA-Sharing-1.0 |
| What it is | Synthetic short stories generated with a ~1,500-word vocabulary — deliberately simple English that a small model can actually fit |
| Used in | Phase 5 (103MB slice) and Phase 8 (200MB, two slices) |

| | Phase 5 | **Phase 8 (v6)** |
|---|---|---|
| Raw | `data/tinystories_raw.txt` 104.9 MB | + `data/tinystories_raw2.txt` 104.9 MB |
| Cleaned to ASCII | `data/pretrain.txt` 103.2 MB | + `data/pretrain2.txt` 103.2 MB |
| Tokenized | `data/pretrain_tokens.pt` | `data/pretrain_tokens_v2.pt` |
| **Tokens** | **26,161,910** | **52,492,768** |
| Stories | 116,509 | 229,640 |

Cleaning (`prepare_pretrain.py`) restricts the text to printable ASCII so the
story corpus and the task data share one alphabet. Story start offsets are kept
so training windows can align to story boundaries instead of cutting mid-sentence.

### 1.2 bAbI — the one piece of curated public task data

| | |
|---|---|
| Source | `Muennighoff/babi` (Hugging Face mirror) |
| Origin | Facebook AI Research — Weston et al., *Towards AI-Complete Question Answering: A Set of Prerequisite Toy Tasks* (2015) — https://arxiv.org/abs/1502.05698 |
| Licence | the bAbI tasks are released under CC BY 3.0 |
| Note | Facebook's original download link is dead; the HF mirror carries the same data as JSONL |
| Used in | Phase 6 onward |

Eight task types: single supporting fact, two supporting facts, yes/no
questions, counting, simple negation, basic coreference, conjunction, compound
coreference. **Capped at 300 examples per task (2,400 total)** — see §6.

### 1.3 Synthetic task data — generated, not written

Every synthetic answer is **computed in Python**, never typed by hand. That is
the integrity guarantee of the whole project: an arithmetic chain cannot be
wrong, because it was evaluated rather than authored. All generators are
deterministic (seed 1337), so any dataset here is regenerable byte-for-byte.

| Generator | Output | Blocks | What it teaches |
|---|---|---|---|
| `make_qa_data.py` | `data/qa.txt` | 36,176 | Small talk, capitals, general facts, 2-digit add/sub, times tables |
| `make_phase2_data.py` | `data/aizen_phase2_train.txt` | 10,000 | Instruction following (5,000) + reasoning chains (5,000) |
| `make_phase3b_data.py` | `data/aizen_phase3b_train.txt` | 15,000 | Targeted fixes for phase-3 failure modes |
| `make_phase6_data.py` | `data/aizen_phase6_train.txt` | 26,400 | 3-digit arithmetic, rebuilt patterns, multi-step, + bAbI |
| — | `data/aizen_phase6b_train.txt` | 22,400 | The same pool with bAbI capped — **this is the line v6 descends from** |
| `make_phase7_data.py` | `data/aizen_phase7_train.txt` | **28,100** | 6b + 5,700 blocks: multi-turn conversation, negatives, false premises |
| `make_eval_data.py` | `data/eval.json` | 400 | **The benchmark — never trained on** |

**v6's fine-tuning pool is `data/aizen_phase7_train.txt` (28,100 blocks),
mixed 70/30 with `data/qa.txt`.**

Pool lineage, verified block by block:

```
aizen_phase3b_train.txt  15,000  ─┐
                                  ├─► aizen_phase6b_train.txt  22,400  ─► aizen_phase7_train.txt  28,100
bAbI (capped 2,400) ─────────────┘         (⊂ aizen_phase6_train.txt 26,400 — the over-diluted dead end)
```

### 1.4 Leakage control

The 400 eval questions were generated **first**, and every later generator
checks its output against `data/eval.json` and rejects collisions. Phase 6's
build rejected 243 collision candidates. Validation on each pool: **0 false
equations, 0 eval leaks.**

### 1.5 What was *not* used

No web scrape, no Common Crawl, no instruction datasets (Alpaca/Dolly/etc.), no
model-generated data from another LLM, no pretrained checkpoint. The
tiny-shakespeare corpus (`data/input.txt`) belongs only to the 0.8M predecessor
described in Appendix B and was never trained into Aizen.

## 2. Tokenization — byte-pair encoding, written from scratch

`tokenizer.py`. Count adjacent pair frequencies, merge the most frequent pair,
repeat until the vocabulary target is reached. No `tiktoken`, no
`sentencepiece`, no Hugging Face tokenizers.

| | |
|---|---|
| Vocabulary | **4,096** (2,048 in Phase 4, widened when the corpus became prose) |
| Base vocab | every character in the corpus ∪ all printable ASCII |
| Compression | **2.64×** on task data, **4.00×** on prose (measured, this 4,096 vocab) |
| Special tokens | `<pad>`=0, `<unk>`=1, `<bos>`=2, `<eos>`=3 |

Merging happens **within words**, using this split:

```python
_SPLIT = re.compile(r"\n| ?[A-Za-z']+| ?[0-9]| ?[^ \nA-Za-z0-9']| ")
```

Three invariants matter more than the vocabulary size:

1. **Every digit is its own word**, so `47` is always `4`,`7` and never a single
   opaque token. Arithmetic survives tokenization.
2. **Newline never merges**, so the `Q:` / `A:` structure stays visible to the
   model as a boundary rather than dissolving into `?\nA`.
3. **Leading spaces attach to the following word**, GPT-2 style, so `" the"` and
   `"the"` are one token each rather than three.

Including all printable ASCII in the base vocab — not just characters observed
in the corpus — is what stopped inference from crashing with `KeyError` on
unusual user input.

*Why it mattered:* at identical parameter count, BPE moved the benchmark 28.75%
→ 35.75%. A character-level model spends its capacity learning to spell.

(The **2.19×** figure quoted in [docs/phase4_bpe.md](docs/phase4_bpe.md) is the
Phase 4 measurement — a 2,048-token vocabulary on the task corpus only. The
numbers above are the current 4,096 vocabulary, measured on both corpora.)

## 3. Architecture

`model.py`, class `Aizen`. Decoder-only Transformer in the GPT-2 layout, ~150
commented lines.

| Hyperparameter | v6 | v0 |
|---|---|---|
| Layers | **12** | 8 |
| Embedding dim | **512** | 384 |
| Attention heads | **8** (head dim 64) | 6 (head dim 64) |
| MLP hidden | **2048** (4×, GELU) | 1536 |
| Context | **512** | 192 |
| Vocabulary | **4,096 BPE** | 73 chars |
| Positions | learned absolute | learned absolute |
| Norm | pre-LayerNorm | pre-LayerNorm |
| Weight tying | embedding ↔ output head | same |
| Dropout | 0.1 | 0.1 |
| **Parameters** | **40,188,928** | 14,298,240 |

One block is `x + Attention(LN(x))` then `x + MLP(LN(x))`. Attention is scaled
dot-product with a causal mask. Nothing exotic — the interesting decisions in
this project are all in the data and the method, not the architecture. The file
was not modified after Phase 0 except to change the class name; config numbers
alone took it from 14M to 40M.

## 4. Training — two stages

```
stage 1  pretrain   plain next-token prediction on TinyStories  ->  aizen_phase8_pretrained.pt
stage 2  fine-tune  answer-masked loss on the task mixture      ->  aizen_phase8.pt  (v6)
```

### Stage 1 — pretraining (`train_phase8_pretrain.py`)

| | |
|---|---|
| Init | from scratch |
| Steps | 16,000 |
| Batch | 12 × 512 tokens, gradient accumulation 2 |
| Tokens processed | ~196.6M (≈3.7 epochs over 52.5M unique) |
| LR | 3e-4 cosine → 3e-5, AdamW, weight decay 0.01 |
| Grad clip | 1.0, with a non-finite-norm guard (see §7) |
| Objective | plain cross-entropy, no masking |
| **Final loss** | **train 1.367 / val 1.356** |

### Stage 2 — fine-tuning (`train_phase5_finetune.py --tag phase8`)

| | |
|---|---|
| Init | `aizen_phase8_pretrained.pt` (weights transfer 1:1) |
| Steps | 5,000 |
| LR | **1e-4** cosine → 1e-5 — deliberately below stage 1 |
| Data | `data/aizen_phase7_train.txt` 70/30 with `data/qa.txt` |
| Loss | **answer tokens only** — question and scaffolding tokens are masked out |
| Windows | example-aligned: every training window begins at a `Q:` |
| **Final loss** | masked train **0.0045** / val **0.0142** |

The low stage-2 learning rate is the point: we are adapting language knowledge
to a task, not learning from zero, and a high LR would overwrite the English
that 16,000 steps just bought.

Answer-only masking is what makes it an assistant rather than a text completer.
In a multi-turn block, **every** `A:` line is masked for loss, which is how the
model learned to resolve "and plus 3?" against its own previous answer.

### Reproducibility

Seed 1337 throughout. Every trainer is chunked and resumable
(`CHUNK_ITERS`, default 250) so a laptop can close its lid mid-run — and the
sampler is **re-seeded per chunk**, which matters enormously (§7).

## 5. Evaluation

`eval.py` against `data/eval.json`: **400 questions, 8 categories, 50 each.**
Written before any improvement work began and **never edited since.**

Two rules held for the entire project:

1. The questions are never modified, and never tuned against.
2. One training run per approved experiment — no quiet retries, no picking the
   best of several seeds.

Scoring is deterministic: each question generates under `torch.manual_seed(1337 + i)`,
so the same checkpoint always produces the same score. `eval.py` auto-detects
character-level (v0–v1b) versus BPE (v2+) checkpoints, so every generation is
scored by identical code.

| | v0 | v1 | v1b | v2 | v3 | v4 | v4b | v5 | **v6** |
|---|---|---|---|---|---|---|---|---|---|
| **overall** | 17.0 | 26.5 | 28.75 | 35.75 | 45.25 | 47.25 | 52.25 | 48.0 | **60.75** |
| arithmetic | 78 | 72 | 86 | 92 | 90 | 98 | 98 | 96 | **100** |
| multi-step arith. | 2 | 56 | 44 | 60 | 54 | 64 | 68 | 68 | **82** |
| logic | 0 | 0 | 10 | 12 | 66 | 56 | 66 | 64 | **72** |
| patterns | 0 | 14 | 14 | 4 | 10 | 20 | 34 | 14 | **48** |
| general knowledge | 48 | 52 | 48 | 48 | 58 | 62 | 62 | 60 | **64** |
| instruction following | 8 | 14 | 12 | 32 | 38 | 40 | 38 | 42 | **50** |
| reading comprehension | 0 | 4 | 16 | 38 | 44 | 36 | 48 | 38 | **68** |
| coding | 0 | 0 | 0 | 0 | 2 | 2 | 4 | 2 | **2** |

At n=50 per category the noise floor is roughly ±7 points, so single-category
moves smaller than that are not evidence of anything.

**v6 is the first generation where every category is simultaneously at its
all-time high.** Every earlier version traded one skill against another — that
see-saw, running from v1 to v5, was a capacity ceiling.

## 6. The eight phases

| # | Phase | Idea | Result |
|---|---|---|---|
| 1 | [Evaluation](docs/evaluation.md) | Build the ruler before touching the model | **17.0%** baseline |
| 2 | [Dataset](docs/phase2_dataset.md) | 10,000 examples, every answer computed | 0 false equations, 0 leaks |
| 3 | [Fine-tuning](docs/phase3_training.md) | Answer-masked loss, example-aligned windows | → **28.75%** |
| 4 | [BPE](docs/phase4_bpe.md) | Stop spending capacity on spelling | → **35.75%** |
| 5 | [Pretraining](docs/phase5_pretraining.md) | Read prose before answering questions | logic 12→66, → **45.25%** |
| 6 | [Hybrid data](docs/phase6_hybrid.md) | Public bAbI + synthetic, dose capped | → **52.25%** |
| 7 | [Conversation](docs/phase7_conversation.md) | Multi-turn, negatives, false premises | 48.0% — a deliberate trade |
| 8 | [Scale finale](docs/phase8_scale.md) | 14M → 40M, the only time params moved | → **60.75%** |

Three findings are worth more than the score:

- **Pretraining is not a scale trick.** At a fixed 16M parameters, reading
  TinyStories moved logic from 12% to 66% with *zero* new logic training data.
- **With external data, proportion matters as much as presence.** The same bAbI
  corpus helped at 2,400 examples and hurt at 6,400 — at 24% of the pool it
  crowded out the skills it was meant to support.
- **Some regressions are purchases.** Phase 7 cost 4.25 points overall and
  bought multi-turn memory. That was approved in advance and reported as a loss,
  not smoothed over.

## 7. Two bugs worth documenting

**The per-chunk reseeding bug.** Every trainer resumes in chunks. Until Phase 8,
each chunk re-seeded the sampler identically — so every resumed chunk redrew
*the same batches*, and the model saw a slice of its corpus repeatedly instead
of the corpus once. It was live from Phase 3 through Phase 8 and it silently
shrank every resumed run. Its fingerprint is a train/val divergence:

| run | final train | final val | gap |
|---|---|---|---|
| Phase 5 pretrain (bug live) | 1.042 | 1.994 | **0.95** |
| Phase 8 pretrain (bug fixed) | 1.367 | 1.356 | **0.01** |

The fix is three lines, re-seeding from `args.seed + 7919 * start_iter`.

**Silent Metal GPU memory corruption.** At 40M parameters, batch sizes above
~20 on MPS produced NaN gradients rather than an out-of-memory error — Metal was
zeroing gradients instead of raising. Found by bisection. The fix is batch 12
with accumulation 2, plus a guard that skips any step whose gradient norm is not
finite.

## 8. Inference

`server.py` — one Flask app, both models, port 8321.

| endpoint | model | behaviour |
|---|---|---|
| `/chat` | `aizen_phase8.pt` | temperature 0.5, top-k 20, stops at newline |
| `/story` | `aizen_phase8_pretrained.pt` (lazy-loaded) | temperature 0.85, top-k 40, runs on |
| `/meta` | — | model card + live benchmark data read from `results/` |

The mechanism that turns a text completer into an assistant is prompt
formatting, nothing more:

```
Q: <your question>
A:
```

Multi-turn works by packing history into that same format, newest-first, until
the 380-token budget is spent — so context is dropped from the *oldest* turn
rather than truncating the current question.

The server binds `host="::"` (IPv6 and IPv4) because Safari resolves `localhost`
to `::1` and cannot reach a server bound only to `127.0.0.1`.

## 9. Honest limitations

- **Coding is 2%.** The model has never read a line of code — TinyStories
  contains none. This is the single largest gap and it is untouched.
- **Phase 8 is confounded.** The scale increase and the reseeding fix landed in
  the same run, so *"40M parameters caused +12.75 points"* is not a claim this
  project can support. Separating them requires a 16M-with-fixed-sampler
  ablation that was never run. (An earlier draft of `docs/phase8_scale.md`
  claimed one variable had changed; it was wrong and has been retracted there.)
- **Three-digit arithmetic still slips**, despite 100% on the eval's two-digit set.
- **Knowledge is thin.** 64% general knowledge means it will state falsehoods
  with complete confidence. It has no notion of "I don't know" beyond the
  negative examples it was explicitly trained on.
- **The benchmark is synthetic and self-authored.** It is a consistent ruler
  across nine generations of one model — it is not comparable to MMLU or any
  public benchmark, and a number from it means nothing outside this project.
- **Batch size is not recorded** in stage-2 checkpoint metadata, and the
  `final_masked_*_loss` fields read `NaN` when a run's last chunk lands exactly
  on the step boundary. The true values are in `results/metrics_*.csv`.
- **It is 40M parameters.** A general assistant needs roughly 10,000× more of
  everything: tokens, parameters, and post-training. The pipeline here is the
  same shape, just very small.

## 10. Build your own — the actual recipe

1. **Write the benchmark first.** Before any model work, before any data. Freeze
   it. This is the step everyone skips and it is the reason every number above
   means something.
2. Write the architecture (`model.py`) — attention, blocks, embeddings, head.
3. Pick a tokenizer that respects your task's structure. Digits and newlines
   were load-bearing here; yours will have their own invariants.
4. **Pretrain on prose before fine-tuning on tasks.** Reasoning comes from
   language, not from task templates.
5. Fine-tune with loss on the answer tokens only, at a lower learning rate.
6. Measure. Diagnose the *failure mode*, not the score. Change one thing. Measure
   again. This loop is 90% of the work.
7. When a change costs you something, write that down too.

## Appendix A — v0, the original character-level Aizen

The first Aizen (`aizen.pt`, **14,298,240** parameters, 8 layers, 384 dim, 192
context) was trained on **exactly one file**: `data/qa.txt`, character-level,
vocabulary of 73 characters, 973,352 tokens (25,390 Q&A pairs). AdamW, lr 3e-4
cosine, batch 64 × 192, 3,000 steps, ~36.9M tokens processed (≈38 epochs), ~45
minutes on MPS.

⚠ **`data/qa.txt` on disk today is not the file v0 was trained on.**
`make_qa_data.py` was later expanded, and the current file holds **36,176
blocks / 1,293,790 characters** — the version above was 25,390 pairs /
973,352 characters. The character vocabulary is identical (73, exact set
match), so v0's checkpoint still loads and scores correctly, but v0's exact
training corpus is not reproducible from the current generator.

Its val loss curve is the most instructive artifact in the project:

| Step | Val loss | What it could do |
|---|---|---|
| 0 | 4.36 | Random characters |
| 100 | 1.81 | English letter statistics |
| 500 | 0.73 | Almost-words: "The capital of I is Palis" |
| 1000 | 0.42 | Real sentences, math format right, sums wrong |
| 1500 | 0.36 | Perfect small talk; first correct sums |
| 3000 | ~0.32 | Fluent answers, reliable two-digit arithmetic |

Spelling → words → grammar → format → facts → arithmetic, in that order. It
scored **17.0%**, and every gain in this document is measured from there.

## Appendix B — the Shakespeare predecessor

Before Aizen, the same architecture at 0.8M parameters was trained on
**tiny-shakespeare** (`data/input.txt`, ~1.1 MB) — the character-level demo
corpus popularised by Andrej Karpathy. Those weights are `tinygpt.pt`. They are
unrelated to Aizen's: Aizen was trained from random initialisation.
