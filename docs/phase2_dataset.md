## Files

- `data/reasoning_train.json` — 10,000 records `{id, category, question, reasoning, answer}`
- `data/aizen_phase2_train.txt` — rendered char-level training text (920 KB)

## Format decision (approved in Phase 2 review)

Reasoning is rendered **inline on the answer line**, not as a separate `T:` line:

```
Q: Aiko has 38 socks, gets 19, loses 19, then finds 2. How many now?
A: First, 38 + 19 = 57. Then, 57 - 19 = 38. Then, 38 + 2 = 40. The answer is 40.
```

Reason: every existing inference path (frozen `eval.py`, `chat.py`, `server.py`)
prompts `Q: ...\nA:` and stops at the first newline — a `T:` line would never be
generated at eval time. The inline format lets the model produce its chain of
thought and final answer in one line, and the frozen eval's last-number checker
scores it correctly with zero changes. The JSON keeps `reasoning` as a separate
field so other renderings can be produced later.

reading_comp 400 · multi_hop 300

Design notes:
- **Instructions matter:** the same facts appear with different instructions
  requiring different outputs (one word vs. YES/NO vs. full sentence via
  `simple_qa` contrast examples), so the model must read the instruction.
- **All deterministic answers are computed by Python** (arithmetic, sorting,
  counting, reversing, case, patterns, comparisons) — never guessed.
- **Reasoning chains are constructed from the computation**, so every
  intermediate equation is true by construction (and re-verified independently).
- Names (Raj, Kim, Eva, Zoe, …), objects, colors, animals, and sequence/passage
  wordings are **disjoint from the eval set's** (which uses Tom/Sam/Ana/…,
  red/blue/green/white, hat/car/ball/…).

| Over the 190-char render limit | 0 |

**Whitelisted arithmetic skeletons:** 324 examples use an eval arithmetic
template shape (e.g. `What is N + N - N?`) with guaranteed-disjoint numbers —
approved policy, since number-generalization is exactly the skill being tested.
All other eval templates are fully blocked.

## Validation (`validate_phase2_data.py`)

Recomputes independently: counts (10,000 / 5,000 / 5,000), unique ids, unique
questions, non-empty fields, full-vocab compliance of the rendered text,
≤192-char rendered blocks, eval exact/template/tuple leakage, **every equation
in every reasoning chain**, final answers vs. last equation, and per-category
answer recomputation (comparisons, sorting, counting, reversing, case,
longest/shortest, numeric patterns, yes/no comparisons, item counts).

## Known limitations

- Reasoning chains are template-generated; linguistic variety is bounded
  (~4 surface forms per skill). Enough to break template-lock, not enough to
  cover free-form phrasing.
- `fmt_three_words` is a small curated set (25 base items × 4 phrasings).
- Deduction covers only one-hop syllogisms (all-X-are-Y / X-cannot-Y).
- Multiplication appears only inside compositions (0–12 range), matching the
  eval design where standalone mul generalization is untestable.
- The 192-char context cap forces terse word problems; no long passages.
- This dataset alone would cause catastrophic forgetting of Phase-0 skills —
  **Phase 3 must train on a mix of this + data/qa.txt**, not this file alone.
